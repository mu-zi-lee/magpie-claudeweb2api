# 验证记录

## 2026-10-10：0.1.2 真实上游 thinking_mode 修复

执行机器：macOS arm64，插件直连 Claude 网页接口。使用用户授权的单个账号凭据，凭据未写入源码、测试夹具或公开日志。

原插件能获取 15 个模型，但 Haiku 5.5 和 Haiku 4.5 的 completion 均返回 HTTP 400。临时后端诊断确认组织查询返回 200、创建会话返回 201，而 completion 的具体错误是 `thinking_mode` 不接受 `none`，要求 `extended`、`standard`、`auto` 或 `off`。临时诊断修改未纳入发行后端。

将 JavaScript 协议适配器的禁用思考值改为 `off` 后，使用当前插件入口及原有预编译后端复测：模型发现成功，`claude-haiku-5-5` 非流式请求和 `claude-haiku-4-5-20251001` 流式请求均返回 HTTP 200、文本 `OK`，并正常结束。流式请求同时覆盖客户端显式传入 `thinking: { type: 'disabled' }`。

现有真实 Go 后端桥接测试中的模拟上游增加了同样的 thinking_mode 校验：修改协议适配器之前该测试复现 HTTP 400，修改后通过。`npm test` 的 25 项测试全部通过，`npm run check` 的六个平台发行后端与校验清单检查通过。Go 后端及二进制未修改，无需重新编译。

测试进程和后端已退出。未更新已安装的 Magpie 插件副本，未发布 npm；其他账号、模型和平台未做真实上游验证。

测试使用临时目录、测试 Cookie 和本地 HTTP 服务；未读取真实 Claude 凭据，也未修改已安装的 Magpie 或原 Claude2api 仓库。

原版宿主集成测试分别使用本地 npm 注册表和仅含 Git 跟踪文件的本地仓库，让真实 Bun 在禁用安装脚本的条件下下载并安装插件。Git 安装回归先在二进制未被跟踪时实际失败，复现 `No packaged backend`；将六个平台后端和校验清单纳入 Git 后，两种安装都通过。验证包内 PNG 通过 `auth.icon` 传给宿主，并检查包元数据中的 `magpie.icon` 与实际 provider 图标一致、Magpie 保存的图片字节与发行图标一致；随后验证中文文本流、客户端 `tool_use`、后端不执行客户端工具、活动组织、停止词、拒绝原因，以及经 `chat.headers` 传递的对话标识和两轮父消息衔接。删除后检查 npm 包目录、注册和依赖记录已移除；等待旧宿主退出后，管道 EOF 触发保留会话清理。

插件会话回归在独立进程中调用 `server({})`，没有宿主扩展字段。验证默认直连、同 ID 会话复用、重复请求和账号/代理变化返回 409、本地截断后的 discard，以及宿主退出后的保留会话删除。另有测试强制结束宿主，确认后端检测 EOF 后退出。

普通卸载不再要求清空 Magpie 共享账号存储、显示记录、模型目录或 Bun 下载缓存。这些数据由 Magpie 自身处理，插件不直接改写共享文件。

协议与后端回归覆盖流式/非流式、取消、慢消费者隔离、工具 JSON Schema 校验、停止词、输出预算、会话历史分支、模型列表缓存及 401/403/429 请求保护。

六个平台后端沿用已构建的发行二进制，本次修改没有改变 Go 后端。Linux / Windows 未在对应系统运行验证。真实 Claude Cookie、Cloudflare 和网页上游访问仍未实测；本地模拟成功不等于真实账号可用。未发布 npm，未部署到正式 Magpie，也未验证正式 GUI 点击操作。
