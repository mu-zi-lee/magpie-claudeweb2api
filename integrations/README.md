# 原版 Magpie 集成验证

插件无需修改 Magpie 源码或应用补丁。日常使用只需在 Magpie 安装插件；下面的源码测试用于开发验收，不是安装步骤。

`magpie-base.json` 记录验收使用的 Magpie 提交。准备处于该提交的源码目录后，从本项目运行：

```sh
npm run build:all
npm run test:magpie -- /absolute/path/to/magpie-source
```

脚本先执行 `npm pack`，再创建一次性 Magpie 源码副本和隔离的 HOME/XDG 目录。仅在副本中添加测试文件，不改动宿主实现或用户安装的 Magpie；保留 Go 原缓存路径，退出后删除临时副本。

测试从临时本地 npm 注册表让真实 Bun 下载并安装发行包，使用原版插件宿主和包内 Go 后端，验证本地图标传递与宿主保存、登录、网页模型发现、文本流、客户端工具调用、停止词、拒绝原因、对话标识传递及两轮复用。上游全部是本地模拟服务，Cookie 为测试值。

删除验收覆盖原版宿主的包与注册移除，并等待旧宿主退出后检查管道 EOF 触发保留会话清理。不要求普通删除清空共享账号、显示记录、模型缓存或下载缓存。

Go 后端通过插件 `proxy` 选项设置代理，默认直连，不自动继承宿主代理设置。测试使用 `direct`。

跨平台构建不等于对应系统的运行验证；真实 Claude 上游和正式 GUI 点击操作仍需另行验收。
